# 媒体解析与证据

## 理解目标与模态分工

先明确用户要提取什么、覆盖哪些分集/区间、需要什么细节。目标是任务相关的语义理解，不是文件数量、OCR字数或文档页数。不要求每次处理所有模态：仅下载不解析，视觉任务可把音频标为不适用；综合内容任务应覆盖相关语言和关键视听信息。

| 来源 | 主要提供 | 不能替代 |
|---|---|---|
| 原音频 | 旁白、解释、例子、语气、发音与声音事件 | 课件结构、无声动作与屏幕细节 |
| 软字幕/硬字幕 | 有时间位置的语言入口与术语线索 | 未写出的口头内容、声音示范；字幕也可能错误或省略 |
| 视频与图片 | 图表、公式、步骤、操作、场景与视觉关系 | 画外解释和声音；OCR只提文字，不解释图像 |
| 用户截图 | 重点信号与细节证据 | 截图前后上下文和全视频覆盖 |
| 评论与弹幕 | 少量纠错、疑点与补充线索 | 原视频或独立可靠依据；复核后仅放附录 |

字幕、ASR和OCR可能同源或复制同一错误，不能当作独立互证。区分“视频作者这样说”和“该说法经外部核实正确”；忠实理解不等于认同所有说法。

## 运行环境与复用

先定位Python/Node、ffmpeg/ffprobe及现有可用依赖。Codex App可用load_workspace_dependencies查运行时。可传显式程序路径；不要要求特定用户目录、NVIDIA GPU或固定模型。裁剪版ffmpeg可能无网络、WAV、AAC编码、null muxer或ffprobe，先检查-version、-encoders、-muxers，不按文件名推断能力。不要未经用户请求安装大依赖或下载模型。

scripts/media.py使用标准库处理媒体检查/字幕审计，调用外部ffmpeg处理媒体。ASR子命令才需要已有numpy、faster-whisper及本地模型。运行--help；所有生成目标拒绝覆盖已有文件，分析新版本用新目录。

## 能力预检

在批量解析前，选开头、典型中段及任务难点的短片段，实际跑完所需路径并阅读/听核/看核结果。短片段的时长由内容决定；语言切换、密集小字、快动作或特殊声音要另取代表样本。

1. 检查真实音视频轨、时长、解码与声音是否存在；测试画面能否辨认任务关键细节。
2. 有字幕则检查语种、所指分集与音画面是否吻合，是否只是摘要或翻译。开头/中段/重点抽核是可信度起点，不证明每句已校定。
3. 需要ASR时，先检查解释器、依赖导入、原生后端、已有模型是否兼容，再实际转写片段，检查时间戳、内容与资源消耗。命令能运行、模型文件存在不构成通过证据。
4. 必要能力失败，记录错误类别、已尝试方法和未覆盖模态。优先尝试已可用的兼容路径；安装新依赖、下载大模型或上传第三方服务不属于默认恢复步骤。

例如：PyAV/tokenizers的DLL失败或CTranslate2不含Whisper后端时，先诊断具体组件。ffmpeg解码输入可绕开部分解码问题，但不能保证解决faster-whisper导入链或后端缺失。未通过真实片段预检，不启动全量ASR。

当音频对目标必需但无可用识别/听取路径，不能默默改用OCR和知识库冒充音频理解。可提供明确的“画面/字幕部分草稿”，列音频未解析、遗漏风险和恢复条件；综合理解仍未完成。用户只要求画面时按视觉范围完成，不把无关音频失败当阻塞。

示例（路径是占位参数，按实际环境替换）：

```powershell
python scripts/media.py inspect --input "output/part.mp4" --ffmpeg "tools/ffmpeg.exe"
python scripts/media.py audio --input "output/part.mp4" --output "output/audio.m4a" --format copy --ffmpeg "tools/ffmpeg.exe"
python scripts/media.py frames --input "output/part.mp4" --output "analysis/frames" --interval 15 --width 1280 --ffmpeg "tools/ffmpeg.exe"
python scripts/media.py audit --subtitles "output/part-a.subtitle.json" "output/part-b.subtitle.json" --duration 600 --output "analysis/subtitle-audit.json"
python scripts/media.py transcribe --input "output/audio.m4a" --output "analysis/transcript.json" --model "models/whisper-small" --device cpu --compute-type int8 --ffmpeg "tools/ffmpeg.exe"
```

## 音频与剪辑

无损提取用-vn -c:a copy，输出容器匹配编码（AAC→m4a、MP3→mp3、Opus→ogg等）；不把容器改名当转换。分析另生成单声道16k WAV/f32le，不替换原轨。剪辑start/end来自本地时间，确认单集而非全集累计；stream-copy切点可能不精确，需要准确边界时用当前支持的编码器重编码。检查输出时长及首尾是否截断关键语句。

## 字幕质量

审计脚本检查空内容、时间戳、内容重复哈希和末尾覆盖，但**不进行语义认证**。duplicateWith比较时间与文本；duplicateTextWith仅比较规范化文本，提示时间稍变但内容相同的情况。不同字幕可能同样错配；重复也可能是视频本就重复，所以只标异常。开头/中段/重点附近核实际内容，保存检查位置与结果。需要字幕可信判定时，应有音视频对照证据，不以最后一个to与时长接近作为通过条件。

采用可信字幕作语言入口时，不强制重复全量ASR，但需要全范围检查字幕的段落、缺口与语言覆盖，重点回听疑点及音频特有内容。硬字幕须核清原图并检查是否覆盖口头内容；采样OCR不等于全字幕提取。有译文字幕时区分原语/译语，精确用词、引语和声音任务回查原音。

字幕不存在、错配或有实质遗漏时，隔离原文件，按必要区间ASR或实际听取；不可直接丢掉音频分支。内容任务中“必要区间”由用户范围及缺口决定，不能只取几段就称完整。保留偏移校正与理由，不无痕篡改原始字幕。

隔离判定针对具体字幕来源：平台软字幕错配，不表示视频内烧录的硬字幕或课件文字也错配。硬字幕与画面文字仍可参与核验；OCR是它们的机器草稿，疑点须看原图。清晰可读只证明看到了某表述，不保证其事实正确或与口头内容逐字相同。

## ASR

只转写必要范围。选择适合设备/语种的本地模型与精度，允许自动语言检测，多语素材不要强塞整段领域初始提示。依赖存在时可用media.py transcribe；通过ffmpeg解码到float32波形，可规避部分PyAV版本不兼容。

JSON包含source、offset、模型/设备、segments时间、低置信和重复标记，complete表示任务已跑完，不表示字词已校对。部分结果保留.partial.jsonl，异常不中途删除来源。长音频按需分段以限制内存，不能把整个多小时媒体解码到内存而不估算资源。

重复句、异常长段、提示词回显、低置信、静音幻觉要听核；标为待核或舍弃引用，不凭上下文补老师原话。代码/公式/专名/英语例句以清晰画面和原音核对。对短片运行通过不等于长视频/所有语言已验证。

低置信字段仅是线索，不直接换算成“正确率”。普通语音转写不适合独立认证孤立音素、音乐、音效或说话方式；任务涉及这些内容时应实际听核，并按需要使用已有专用工具。不具备听取能力或仅做ASR时如实写明。

## 视觉

静态课件可定时采样加变化去重；实际画面切换快时缩短间隔或用场景切换检测。动作/操作分析用更密帧与连续片段，不仅依赖幻灯片OCR。附带frames脚本采用显式seek时间并记录时间点，不宣称识别全部转场；先抽几帧判断任务是否可完成。

OCR按画面语种选择，含混中英可分别OCR再核图。Windows原生OCR可用，但系统PowerShell的PSModulePath有时受宿主影响；只对子进程恢复系统模块路径，不改用户全局配置。水印、弹幕、讲师摄像头与课件区域分开；不要把弹幕观点混进视频教学事实。

用户截图的内容处理：识别核心信息→对齐视频与上下文→说明重要性→补适用条件/正反例/可迁移应用。不是每次都需要练习，也不是每次都要文档；具体产物由用户目标决定。需要某个原图的结构或视觉细节时保留必要图，不能无条件禁止图片。

对图表、空间关系、示范动作和操作顺序直接看图/连续片段；OCR文字只是索引。依据场景变化、字幕主题切换、声音事件与用户重点增补检查，记录固定采样未捕获的风险。细小字体先提高可用源清晰度/裁切，不把放大模糊图当新增证据。

## 时间对齐与冲突处理

以BV、分集/CID和该集本地时间作为统一定位；平台章节、弹幕时间、剪辑时间和ASR分段可能有偏移，记录转换而不混用全集累计时间。一个语义段可以对应多张图和多个音频片段，不机械按固定秒数拆意义。

遇到字幕/ASR/课件冲突，回查该位置前后原音与连续画面；文字模态多数一致不能定真假。能解决的记录纠正及依据；无法解决的保留分歧/待核，不编造精确引语、公式或动作。外部知识只能补适用条件或验证事实，不能还原未知的原视频内容。

### 按具体主张交叉核验

以“一个术语、例子、规则或动作”作为核验单位，先核BV/分集与时间，再看相邻语义上下文；ASR窗口、采样帧时间不当作精确句界。证据选择取决于要判断什么，不按模态多数表决：

| 要核的内容 | 可采用的证据与结论 | 仍需分开的判断 |
|---|---|---|
| 术语、拼写、符号、屏幕步骤 | 同时间ASR/字幕上下文加清晰原图，可校正草稿并确认展示内容 | 不能因同音词被ASR选中就覆盖清晰拼写；不由文字反推真实声音 |
| 作者的解释、条件、否定或因果 | 读相关语言段，核清硬字幕/课件并检查前后语义；画面只覆盖部分时保留口头缺口 | “作者这样说”与“外部事实成立”分开；课件标题不能代替完整解释 |
| 图表关系、动作与过程 | 直接看对应图及必要连续帧/片段，结合相关语言解释 | 单张示意图不证明讲师实际执行了动作，也不证明完整时序 |
| 音质、语气、音效、正确/错误声音差异 | 图文先确认示范对象/标签，实际实现用原音听取或合适声学方法核查 | ASR同词或字幕一致不能认证声音实现；只能明确局部待核 |

每项保留“主张—来源时间—采用证据—冲突/修正—结论—限制”。证据须写明来自原音、ASR、软字幕、硬字幕、课件还是用户图片，不把同源文本算作独立真值。若硬字幕与ASR实质冲突而原图不能解决，标出分歧，不凭知识替作者选择原话。

可确认的教学/语义内容进入理解记录，声音特有或局部缺口另列待核。不要因不能逐一认证声音示范而把所有文字要点一律搁置，也不要把部分已确认要点扩展成整章/整课已验证。用户截图继续作为重点信号，整理其含义与适用条件而非默认粘贴。

## 中间理解记录

先形成理解记录，再生成笔记、摘要、翻译、检索索引、剪辑方案或其他用户产物。规模小可在一个Markdown表/列表中完成，规模大可用JSON及来源索引；不强制特定文件名或专业文档模板。

每个任务相关语义段至少包含：

- **定位**：BV、分集/CID、起止时间、原文件/字幕段/帧位置；估计边界标明估计。
- **内容**：主题、作者主张、解释逻辑、步骤及条件、重要例子/反例；按素材类型选择适用项，不机械凑栏目。
- **视听补充**：关键图像结构、屏幕步骤、字幕外口头解释、示范及声音事件；未处理部分明确标注。
- **证据状态**：实际采用的模态、已核对位置、逐项修正与结论；来源内容核定、外部事实评价和声音实现分别标明，保留冲突与待核项。释义不伪装成逐字引语。
- **外部补充**：与视频内容分开，说明用于解释还是事实验证；只用知识库时不声称已检索权威资料。

示例结构：

```text
定位：<BV / 分集CID / 本地起止时间 / 原文件与帧或字幕索引>
主题与解释：<作者说了什么、为什么、适用条件>
步骤或例子：<本段实际内容，非适用项省略>
视听补充：<关键画面关系、字幕外解释、声音示范>
证据状态：<采用模态、核对位置、观察/推断、冲突/待核>
外部补充：<独立标记的解释或验证依据，没有则省略>
```

不要只拼接转写/OCR当理解。检查相邻段关系、论证与操作依赖、例子对应观点、关键术语前后一致；不能用“丰富知识扩展”补偿缺失原始证据。评论和弹幕不进入此正文内容，另按[社区内容复核](community.md)保存附录记录。

## 覆盖与完成

按用户选定范围建立分集/章节覆盖表，分别记录语言内容、音频特有信息、关键视觉内容、字幕可信度、理解记录与未解决问题。状态用“已处理、抽样、待核、失败或不适用”，配实际时间范围和方法；标为不适用必须说明与当前任务无关。

- **媒体就绪**：文件和轨道/时长检查通过；不是已理解。
- **提取完成**：所选文本/帧/音轨取得；不是语义正确，也不是视听信息全部覆盖。
- **部分理解**：已有时间对齐的理解记录，但必要区间/模态未处理或关键问题待核；可交付明确标识的部分结果。
- **所选范围理解已验证**：全范围语言内容有可信字幕、ASR加重点核对或实际听取路径；必要视觉和音频特有细节有对应检查；理解记录贯通主要段落且关键冲突已处理，余下不确定项披露。视觉/声音单项任务只检查该任务必要内容。

最后一种状态不意味着逐秒观看或逐字人工听校。给出实际方法、范围和抽核程度，不用一个含糊“完成”覆盖所有阶段。缺字幕可以完成，但必要音频未解析不能宣称综合完成；未获取评论不影响主体完成。

覆盖表可同时记录“术语/例词已核，声音实现待核”等局部结果。原始ASR/OCR继续保留草稿状态，核定内容写入关联理解记录；不覆盖机器原件来伪装人工校定。审查已有成果时，把建议分为纠错、遗漏补充、来源/知识补充分界和仅需补证据；保留无需修改的正确内容，按用户授权决定是否生成新版。

长视频增量处理与保存记录，区分完成/待处理分集。多语言或不同格式交付共用同一理解记录，继承不确定性和覆盖边界，不把重写/翻译当成新的媒体核验。

## 验证边界

保留精简来源索引、覆盖表与不确定项。实际文件probe、播放/解码抽样、内容对照三种证据分开；容器检查不等于完整解码，ASR完整不等于语义正确。分析状态放独立记录或扩展字段，不改写下载manifest的原有状态语义。最终格式另用对应技能，保留原件和版本。工具不可用时说明限制，并在任务范围内尝试现有替代路径；不能把失败写成完成。
